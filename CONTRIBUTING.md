# Contributing to LLMs Robot Arena

Contributions to the simulator, sandbox, viewer, tests and documentation are welcome. Please describe the problem and the behavior your change produces, and include relevant validation in your pull request. Keep project text, comments and interface messages in English.

## Model submissions

We do not accept pull requests that add new models or model-attributed bots to the official catalog. We cannot verify that a submitted controller was actually generated by the claimed model, thinking level and coding harness.

If you would like a model included, contact Simone Nigro at [nigro.simone@gmail.com](mailto:nigro.simone@gmail.com) to arrange access through an API key. Simone will generate and evaluate the controller and add it to the catalog. Use the email to arrange access; do not put API keys in issues, pull requests or repository files.

You are welcome to build and test your own controllers locally in Bot Lab or through the CLI. Local experimentation does not register a model in the official catalog. See [AGENTS.md](AGENTS.md) for the complete bot contract, evaluation protocol and black-box policy.

## Development

Use Node.js 24 or newer. Install dependencies and start the viewer:

```sh
npm ci
npm ci --prefix apps/web
npm start
```

Open http://127.0.0.1:8080. On Windows PowerShell, use `npm.cmd` if execution policy blocks `npm.ps1`.

Before submitting a platform change, run:

```sh
npm test
npm run lint --prefix apps/web
npm run build
```

Add tests for behavioral changes where they help prevent regressions. Explain any checks you could not run. Rule changes must keep the documented constants and engine tests consistent.

## Repository files

- `bots.json` is the official controller catalog. Keep the model name separate from `thinking`, `harness`, provider and development provenance. Bot IDs and source paths are stable identifiers.
- Root `match-*.json` files are optional, local CLI input manifests selecting bots for an evaluation. Create them manually as needed; they are ignored by Git. The runner writes its output to `results/`.
- `dist/`, `results/`, `artifacts/` and dependencies are generated or local files and should not be committed.
- The viewer computes its opening match automatically. Playback tests generate their own engine fixture; no bundled demo replay is needed.

Controller implementations remain black boxes when working on the project. Do not inspect competing source files or hidden state to develop a bot. Follow the full instructions in [AGENTS.md](AGENTS.md).
